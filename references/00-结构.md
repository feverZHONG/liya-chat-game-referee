## 结构：一游戏一文件夹

```
chat-game-referee/
├── SKILL.md              通用层（铁律 / 渲染 / 节奏），游戏无关
├── scripts/              引擎、自测、通用工具都在这层，靠文件名分（脚本必须待顶层）
│   ├── game.py               统一入口：只分发、不改引擎行为（`bin/game`，子命令 = 游戏名）
│   ├── minesweeper.py        扫雷引擎（裁判向：藏答案）  + minesweeper_selftest.py
│   ├── gomoku.py             五子棋引擎（对擂向，档 1–4）+ gomoku_selftest.py / _audit.py / _bench.py
│   ├── liars-dice.py         大话骰引擎（对擂向：暗骰/叫数）  + liars-dice_selftest.py
│   ├── liars-deck.py         骗子牌引擎（对擂向：暗牌/诈牌）  + liars-deck_selftest.py
│   ├── dice-duel.py          掷骰决斗引擎（对擂向：无暗牌、RNG 走盐值承诺）  + dice-duel_selftest.py
│   └── ledger.py             跨游戏战绩台账              + ledger_selftest.py
├── games/                一游戏一文件夹：规则约定、坑（有教程的还放 tutorial.md）
│   ├── minesweeper/rules.md
│   ├── gomoku/rules.md
│   ├── liars-dice/rules.md + tutorial.md
│   ├── liars-deck/rules.md
│   └── dice-duel/rules.md
└── references/           搬东西 / 配教程时才翻（铁律里的长子条都在这儿，见下方「翻哪份」）
    ├── fairness-and-blindfold.md    铁律 5 展开：盐值承诺 / 蒙眼 / 三条泄露路 / 牌面只走图
    ├── selftest-discipline.md       铁律 7 展开：四件体检 / 见到 FAIL 先分锅 / 断言的边界 / 哨兵串
    ├── change-authorization.md      铁律 8 展开：批过的口径怎么铺 / 决定权递回 / 自测 stale 两条
    ├── postmortem-audit.md          铁律 9 展开：解说与引擎分开评 / 更准≠更好玩 / 采样破确定性
    ├── external-rules-crosscheck.md 铁律 10 展开：官方口径三源交叉 / 自创标注 / 文档对齐
    ├── cli-forms.md                 铁律 3 细节：盘型预设 / 列数上限 / CLI 能算的数别现算
    ├── liars-dice-variants.md   大话骰变体 + A/B/C 升级计划 + 外部参考 + 骗子牌官方口径 / 蒙眼审计
    ├── settlement-close.md      收桌 `close` 的落地套路 + 坑 + 铁律 11 子条（加新游戏 / 改收尾时先翻它）
    └── tutorial-guide.md        聊天侧教程怎么写 + 暗牌游戏教学局走法（第八节 / 引擎口子现状）
```

**翻哪份**：铁律 3 → `references/cli-forms.md`｜铁律 5 → `references/fairness-and-blindfold.md`｜铁律 7 → `references/selftest-discipline.md`｜铁律 8 → `references/change-authorization.md`｜铁律 9 → `references/postmortem-audit.md`｜铁律 10 → `references/external-rules-crosscheck.md`｜铁律 11 → `references/settlement-close.md`｜大话骰变体 / 蒙眼实现坑 → `references/liars-dice-variants.md`｜教程怎么写 → `references/tutorial-guide.md`｜维护状态 → `references/maintenance.md`

**命名：脚本 `<游戏名>.py`、文件夹 `<游戏名>/`，两边同名；一个游戏的附属工具挂 `<游戏名>_*.py`。** 加新游戏 = 建文件夹 + 写引擎 + 在下面「游戏索引」添一行 + 在 `scripts/game.py` 的 `SUBS` 里挂一行，别另起炉灶。脚本必须待在 `scripts/` 顶层——它得当命令跑（`python3 scripts/<游戏名>.py ...`），路径越短越顺；文件夹只装讲规矩的那类东西。

**搬新游戏进来之前，先过准入门槛（三条）**——缺一条，搬过来也是死棋：

| # | 门槛 | 判据 |
|:--|:-----|:-----|
| 1 | 一回合一条消息装得下 | 盘面小、纯文字画得出来；大棋盘要么缩盘要么每手出图 |
| 2 | 状态小、可落盘、可捞回 | 一局塞进一个 `temp/<游戏名>.json`，会话过期还能接上 |
| 3 | 信息不对称那部分能交给裁判持 | 藏答案 / 暗牌 / 底牌裁判端持得住；反过来要**玩家人肉藏秘密**的（猜数字 / 读心）在聊天里不成立 |

**搬的实质是重写交付形态**：老代码能留的是引擎、规则、教程大纲；终端 UI 那套（`input()` 主循环、清屏、启动器）全丢。用户丢来**候选**问「这个怎么样 / 可以考虑一下」时，要的是分档＋建议＋一句「点一个」，不是立刻实现（方向他定）。

**先给判断，别抢跑**：评估外部参考（开源项目 / 别人的同类游戏 / 一条参考视频）先摸清「能给本项目什么」——读它的源码 / 拉它的字幕，只留可借的那几样（规则、算法、AI 设计），别整个照搬；全文速记落 `workspace/memory/video-notes.md`，skill 里只挂指针。
