# 铁律 3 细节 · 一手一命令的形态

> 本文件是 SKILL.md 铁律 3 的展开，规则主文在 SKILL.md。

> 规矩本身（用 CLI 别手改 json、命令长什么样、统一入口 `bin/game`）在 SKILL.md 铁律 3；这份是下面的长子条。

   - 开局给尺寸：常用盘型走预设 `new C3 --preset quick`（quick 6×6/5、beginner 9×9/10、inter 16×16/40），自定义才用 `--w/--h/--mines`——尺寸与雷数写进状态文件，之后 open/flag/show 自动识别，别重复传参。**列数上限 26**（坐标只有 A–Z 单字母），超宽盘 CLI 直接挡下。
   - **手机端列数按字号算，别凭「16 列看不了」拍脑袋**（2026-09 实测推算）：拿一张群聊截图量三个数——汉字宽、半角宽、行距。实测 720px 宽设备上汉字 ≈34px、半角 ≈17px、行距 ≈40px，即代码块每行约容纳 30–35 个半角字符。盘面每格 `■ + 空格` 占 **3 个半角宽**（`■` 是全角），行首「4 格缩进 + 2 字符行号」再占 6 个 → `(30~35 − 6) ÷ 3 ≈ 8~9`。**结论：裁判局盘宽上限定 8 列**（6×6 舒适、8×8 可用、10 列贴边），纵向 22–25 行，盘高基本不是瓶颈。
     - **两个再吃宽度的变量**：① 插旗后 `🚩`/`💥` 是双宽，卡边的 10 列会当场断行；② 用户把系统字体调大一级、或换更窄的设备，容量再打八折。要更宽的盘只能换纯 ASCII 符号（拿可读性换宽度，通常不值）。
     - 被问「这字号能玩多少格」时，**先量、再算、把中间数一起报**（字宽／行距／每行字符数／可用列数），数是他自己能复核的——只给结论没法验证。
   - **凡是 CLI 能算的数，别在回话里现算**：每手的「未翻 N（含旗 M）｜剩余空格 K｜雷 L」照抄盘面自带的统计行；摊牌的哈希照抄 `reveal` 的「独立复算 → 一致 ✓」。手算漏过旗格、口径报错过（实战各一次）。
