# 聊天侧教程编写规范

> 从老仓库两件东西改出来的：老教程编写指南（443 行，终端时代的方法论）+ liars-dice 的 tutorial（629 行，唯一一门写成的实战）。
> 老那份管的是「阁下坐在电脑前，按回车走完 8 节课」。聊天里那条路不通——这份管聊天侧。
> 什么时候翻：要给一门游戏配教程、或把老教程搬进来时。

---

## 一、尺子：什么时候才值得写

聊天里教程的代价比终端高——**它要占对话回合**。所以门槛抬高一档：

| 写 | 不写（给一张速查卡就够） |
|----|--------------------------|
| 3 条以上特殊规则，新手会懵（大话骰、21点） | 一句话讲完（扫雷、掷骰、井字棋） |
| 不是人人都熟（21点的叫牌、24点的凑法） | 人人会（五子棋规则、井字棋） |
| 有东西可教（活三冲四、什么时候开盅） | 没东西可教（猜拳） |

- **机制简单但有推理 / 策略**的（扫雷、五子棋）：不做全套教程——给一张**速查卡**（一屏放完）+ 实战里点到为止的提示。扫雷的 `hint` 就是照这个设计的：只给形状，不给结论。
- 一句话能讲完的：README 一行，别开课。
- 现在手上这两门（扫雷 / 五子棋）按这把尺子**都不该写全套教程**；真正需要的是还没搬进来的大话骰 / 21点。

---

## 二、两层分法（最要紧的一条）

老教程把教学文字全塞进 `TUTOR` 字典——**写死的台词 + 分支函数**。终端里没别的选择；聊天里照搬就亏了：本天使会说话，阁下随时能插一句「为什么」「再来个例子」。

所以聊天侧把教程拆成两层：

| 层 | 落在哪 | 管什么 |
|----|--------|--------|
| **大纲** | `games/<游戏>/tutorial.md` | 这一课教什么、摆什么局面、阁下要做什么、怎么算过、答错怎么兜 |
| **话术** | 本天使，现场说 | 怎么讲、举什么例子、阁下卡住时换个什么说法 |

**大纲里不写台词。** 老仓库里最不该照搬的，恰好就是那 629 行台词。

## 三、终端 → 聊天：七处必须改

| | 终端（老教程） | 聊天侧 |
|---|---|---|
| 篇幅 | 一屏 20 行，按回车继续 | **一条消息只讲一个概念 + 抛一个动作**；8 课瘦到 4–6 课 |
| 推进 | `input("按回车继续")` | 阁下做完那一下就走；不催、不复述 |
| 进度 | 内存，退出即丢（老指南自己列在「可以改进」） | **落盘** `temp/<游戏>.tutorial.json` 存关卡游标；说「接着教」就捞回来 |
| 输入 | `parse_bid()` 精确解析 | 自然语言——「我下中间那个」也得认；判不准**先反问一句**，别硬猜 |
| 答错 | 错 3 次给答案、6 次跳过 | 错两次就**换说法**（换比喻 / 降难度），第三次直接演示一遍——不卡人，也不让人下不来台 |
| 局面 | 硬编码手牌（不许随机） | 同样不许随机，而且**引擎得给「摆局面」的口子**——不能靠本天使嘴上描述棋盘 |
| 毕业 | 打印启动命令 | **直接开一局**（老指南 7.2 自己写的那条遗憾，聊天里免费解决） |

## 四、课程表模板

一课一行，六列：

```
| # | 教学点（一句话） | 局面（怎么摆） | 阁下做什么 | 怎么算过 | 答错兜底 |
```

课数按复杂度定：★★★ 四课、★★★★ 五到六课。**最后一课永远是「真对局的前几手」**。

---

## 五、落点（不许另起炉灶）

- 大纲：`games/<游戏>/tutorial.md`
- 进度：`temp/<游戏>.tutorial.json` → `{game, 关卡, 已完成[]}`
- 引擎：**同一套 CLI 加一个 `tutorial` 子命令族**（`start` / `next` / `status` / `stop`），只管摆局面 + 判动作——**这是规划落点，不等于已落地**；开课前先用 `--help` 核一遍，没口子的课怎么走见第八节
- **不给教程另写一套引擎**——老仓库是独立 `tutorial.py` 去 `import game`，聊天侧再长一份就是三份副本，必漂移
- 入口：阁下一句「教我玩」/「教程」，不报命令
- 自测：摆在那个游戏的 selftest 里，教程态全流程走一遍

## 六、样例：大话骰（老 8 课 → 聊天 5 课）

老版：认识骰子 → 1 点万能 → 叫骰 → 质疑 → 斋/飞 → 劈 → 残局 → 毕业（8 课 / 约 10 分钟 / 无存档）。

聊天版：

| # | 教学点 | 局面 | 阁下做什么 |
|---|--------|------|------------|
| 1 | 骰子是暗的，每人 5 颗 | 硬编码一手牌 | 看一眼自己的，说声「好了」 |
| 2 | 1 点能当任何点数 | 同一手牌 | 报「我这儿有几个 6」 |
| 3 | 叫骰只能往高叫 | 本天使先叫「2个4」 | 接一个合法叫骰 |
| 4 | 觉得吹牛就开盅 | 摆一个必开的叫骰 | 决定开还是接 |
| 5 | —— | 真局 | 直接开打 |

斋 / 飞 / 劈不占独立课——塞进第 3、4 课的**答错兜底**里，用到才讲。

## 七、写完怎么验

自问三句，缺一句就别交：

1. 每条消息是不是**只有一个概念 + 一个动作**？
2. 中途走开再回来，能不能从 `temp/<游戏>.tutorial.json` 接着上？
3. 阁下的动作说得含糊时，是**先反问**还是硬猜？

---

## 八、暗牌游戏的课：老师不能核学员的骰

暗牌游戏（大话骰 / 骗子牌）里本天使既是老师又坐对面——**蒙眼条款下手里没有阁下的牌面**，「数对（含 1）」这种核对根本做不了，硬核就是偷看盅。两类课分两种走法：

- **只看自己手牌的课**（骰是暗的 / 1 万能）：直接在真局上走，零成本。判定降级成**形式通过**——回话里明说「本天使不核，核了就是偷看你的盅」，别假装验过了。
- **要特定局面的课**（本天使先叫「2个4」、摆一个必开的叫骰）：前提是引擎有「摆局面」的口子。没口子时用真局的自然流程替代——让阁下先起叫 → 引擎应手当示范 → 阁下往上接；固定手牌的教具盘还得等口子，别用嘴描述局面凑（见第三节「局面」）。
- **教学局不进战绩**；最后一课是「真对局的前几手」——真局当教具的，接着往下打就行，不用另开一盘。
- 进度落 `temp/<游戏>.tutorial.json`，键用英文（与引擎状态文件同风格）：`{"game": "...", "level": N, "completed": [..]}`。一课一条消息、一个概念 + 一个动作；被别的事岔开，回来读这个文件接着上。
