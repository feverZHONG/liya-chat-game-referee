# 扫雷裁判 · 具体约定

## 规则（本库口径）

- 10×10，10 颗雷，列 A–J × 行 1–10。
- 盘型预设：`new C3 --preset quick`（quick 6×6/5、beginner 9×9/10、inter 16×16/40）；自定义用 `new C3 --w 6 --h 6 --mines 5`——`--w/--h/--mines` 只在 `new` 时生效、且显式给的值覆盖预设，尺寸/雷数写进状态文件，后续自动识别。**列数上限 26**（坐标只有 A–Z 单字母，超宽 `new` 直接挡下）。
  - **6×6 快速局口径**：36 格 5 雷 ≈14%（比初级 12.3% 略密），首点安全区吃掉 9 格，余 27 格布雷池——即 `--preset quick`。
- 数字 = 周围八格雷数；揭开空白（0）自动连通展开。
- 踩雷即终局（真踩，无复活）；全清即胜。
- 玩家指令：`D2` = 翻开；`标 D2` = 打/取消 🚩。
- 两种文字样式：`--style classic`（默认，■/·/数字/🚩/💣/💥）/ `--style emoji`（🟦⬜1️⃣🚩💣💥，全 emoji 宽度一致、不易歪列）。
- 雷的画法：`💥` = **真踩中的那一颗**（终局 BOOM）；`💣` = 摊牌 `--reveal-all` 摊开、但没踩中的雷。
- 首点安全区：`new D2` 会把 D2 及其八邻排除在布雷池外 —— 开局体验好，写清楚就算公平。

## 坐标 ↔ 索引

- `X#` → `(row=#-1, col=ord(X)-65)`，**0 基**。json 里 `counts` 的键是 `"r,c"`。
- 半角大写、行号两位不限（`A10` 合法）。

## 落盘路径

| 文件 | 内容 |
|------|------|
| `temp/minesweeper.json` | 盘面：`mines`（终局答案，定死后不改）+ `counts` + `opened` + `flagged` + `steps`（手数）|
| `temp/minesweeper.commit.json` | 公平承诺：`salt`（保密）、`mines`（保密）、`hash`（可公布） |
| `temp/minesweeper.py` | CLI 本体（`scripts/minesweeper.py` 的部署副本） |
| `workspace/records/minesweeper/` | **收桌后的存档**：`<日期>-<盘型>-<结果>-阁下.{md,json,.commit.json}` + 由 `close` 自动重建的 INDEX.md |

## 收桌（一条命令）

终局（BOOM 踩雷 / CLEAR 全清）之后：

```
python3 minesweeper.py close                    # 存档 + INDEX 重建 + 台账一笔 + git 提示
python3 minesweeper.py close --no-ledger        # 只存档
```

- 把 `temp/` 那份盘 + 承诺拷成一档，md 从盘面与 `check`/`reveal` **现生成**（终局盘面 / 自洽校验 / 承诺复算全是脚本输出，别手写），INDEX 按各档 md 的 `<!-- meta -->` 重建。
- 防呆：没终局不收；同一盘重收被挡（状态里落 `closed_as` 戳）；同一天连开两盘 slug 自动加尾号。
- **口径**：本天使执盘（裁判），胜负按盘算——**阁下踩雷 = 本天使胜，阁下全清 = 本天使负**；台账照这个记（`--note` 会写明「裁判局」）。

## 公平承诺流程

> 三条命令走完，别手写、别手算：`python3 minesweeper.py check`（自洽校验）→ `commit`（封存盐+答案，打印可公布的 hash）→ `reveal`（终局摊开盐+答案）。

1. 定盘后：`salt = secrets.token_hex(16)`，`hash = sha256(salt + "|" + json(sorted(mines)))`。
2. **只公布 hash**；盐和答案留在 commit 文件里。
3. 被质疑时同时给：自洽校验结果（已翻开格数字 vs 按 mines 重算，须 0 处不符）+ 该 hash。
4. 终局（BOOM / CLEAR）后摊开 salt + mines，让对方自己复算（`reveal` 连独立复算一起打，一致/对不上都在输出里）。

## 坑

- **先跑一遍再上桌**：`new D2` → `open` → `flag` → `check` → `commit` → `reveal`（末局对哈希）→ `CLEAR`/`BOOM` 走一遍，确认没崩。已实测修掉两个必崩点（见下）。
  - 改的是**看得见的东西**（符号画法、对齐、统计行措辞）时，再拿真实终局盘面回放一遍：`python3 minesweeper.py show --reveal-all --state temp/minesweeper.json`——selftest 跑的是临时小盘，符号歧义和列歪它看不出来。
- **坐标类型**：`new_board` 里存 tuple，落盘时才转 list。存 list 会让 `flood` 里 `set(mines)` 直接 `unhashable type: 'list'`（曾经 `new` 一跑就崩）。
- **踩雷后别让盘崩**：已开的雷格在 `counts` 里没有条目，`render` 若无脑取数会 KeyError（踩雷后 `show` / 下一手全崩）。开着的雷格一律画 💥。
- **💥 只给真踩中的那一颗**：终局 `--reveal-all` 若把 5 颗雷全画成 💥，玩家会当场以为你踩雷输了、最后一手白干（实战被问「该不会在最后一步完蛋了吧」）。摊开没踩中的雷画 💣，踩中的画 💥；`show --reveal-all` 会附一行图例。
- **自测的收尾断言要重读落盘状态**：`play_to_clear` 若拿开局那份 `opened` 一路跑，flood 顺手开掉的格在后续几手变成空转，「CLEAR 全清」就恒定 FAIL 而没人发现——安全网自己破了洞。每手重读 json，并补一条「全清后未开格 == 雷数」的硬断言。改了 CLI 见到 FAIL，先用 `git show HEAD:<脚本路径>` 取改动前的版本跑同一套对照，分清是改动的锅还是自测本来就坏。
- **开重复格 / 开旗格**：都要「不动作 + 一句提示」，别默默无反应——玩家会以为你没干活，反复报同一格。
- **会话过期**：QQ 会话断线后没有上下文，玩家照样直接甩坐标。先 `find "$GAME_HOME/temp" -maxdepth 2 -name '*.json'` 找盘，别急着重开。
- **别把盘写进 skill / md / memory**：答案只活在 commit 与 state 文件里，写进长期文件等于把题送出去。
- **别手改 json**：`opened` 漏格、索引顺序错都会让盘面自相矛盾，一律走 CLI。
- **部署副本会漂移**：`temp/minesweeper.py` 若是现场手搓的版本，会缺 `check`/`commit`/`reveal`（实战踩过：公平自证时子命令不存在，只能临时内联重算）。续局前先从 skill 拷一份 `scripts/minesweeper.py` 覆盖掉，别每盘重写；改完再 `diff` 一次确认两边一字不差。
- **文字不能丢，图只是附加**：QQ 手机端代码块常不是等宽字体，`--style emoji` 也兜不住时用 `--png`（路径可省，默认写 `<state同名>.png`）出图（Pillow 画格：立体未开 / 浅底已开 / 经典配色的数字 / 红旗 / 黑雷，踩中的那颗红底白雷，摊开的雷灰底黑雷；图自带统计行），回话里把 `MEDIA:路径` **附在字符盘面之后**。文字盘面是主线：可复制、图加载不出也照样能玩——只发图等于把线赌在图片上。中文用系统 CJK 字体（wqy-zenhei）、格内数字用 DejaVu——**换机器后字体不在会退化成豆腐块**，发图前先看一眼再发。
- **改「口径」要五处一起改**：符号画法、统计行措辞、摊牌话术同时活在 ① `scripts/minesweeper.py` 的文字渲染 ② `render_png` 的图内标题与图例（统计行走 `tally()` 单点，但**图例文案是另写一份的**）③ `temp/` 部署副本 ④ SKILL.md 渲染约定 ⑤ 本文件——只改一处，下一局就按旧口径来（文档比代码更容易被信）。全部对齐再收工。
- **被质疑时给结果不给过程**：跑 `check` 报「N 格已翻开，0 处对不上」+ 可公布的 hash；一整套校验代码别贴在聊天里。
- **渲染对齐**：🚩 和 💥 是双宽，混排时列会歪一点点，可接受；别为了对齐改用纯 ASCII 丢掉可读性。
- **口子由 `hint` 出，别肉眼推**：`hint` 列「没开邻居 ≤2 的数字」，只给形状不给结论（是雷/是安全一律不说）——手写口子容易看漏、数错。
- **踩雷即终局，摊牌一步到位**：`open` 到雷会自动接 `reveal`（有 commit 文件才摊）；别再手敲一遍。
- **「未翻」含插旗格**：报给玩家的「未翻 N 格」= 所有没翻开的格（插旗的也算），别只数裸露的 ■（实战一次报漏了 3 面旗，被自己纠正——玩家拿这个数推「还剩几格安全格」，报错会影响他判断）。这行现在由 CLI 直接打（`未翻 N（含旗 M）｜剩余空格 K｜雷 L`），回话照抄。
- **「剩余空格」≠「未翻格」**：`剩余空格` = 总格 − 雷 − 已开（安全格未开数）。`剩余空格 > 0` 而所有未翻格都插着旗 = **旗底下压着安全格（有错旗）**，盘就是卡在这儿没清。两个口径别混着报。
- **玩家会报错坐标**：最常见是「把数字行当成旗行报」——旗在 A6/B6/E6/F6，玩家报 A5/B5/E5（上一行的数字格）。**别照单执行**：`flag` 是 toggle，对已翻开的格执行等于把旗插到开格上。先指出「那几个是数字格、没旗」，让他报准。
- **别替玩家选撤哪面旗**：那是报答案。只给形状（「C6 的 2 和 D5 的 2 各自只剩两格没开」），撤哪面由玩家自己定。
- **`new` 会自动清掉上一盘的 commit 文件**（旧盘终局后残留，会让新盘的 `commit` 直接被跳过）——别手工删。
- **别删存档 md 头部的 `<!-- meta {...} -->`**：INDEX 是从它重建的——删了那一档，下次收桌它就整行消失（存档还在，但没人找得到）。
- **收桌口径别混**：`close` 记台账用的是「本天使执盘」那套（踩雷 = 本天使胜）；`--note` 默认已写明「裁判局」。
